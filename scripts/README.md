# Waypoints Data Pipeline

`scripts/extract_data.py` exports the Waypoints Google Sheets into the JSON and GeoJSON files consumed by the website map. Each sheet is processed in sequence: UUIDs are assigned to any new rows, missing coordinates are geocoded, route geometries are generated, the results are written to disk, and — unless `--no-upload` is set — the enriched data is written back to the spreadsheet.

## Outputs

| Sheet    | File(s)                              | What the script adds |
|----------|--------------------------------------|----------------------|
| Overview | `docs/resources/data/overview.json`  | Parses `photos` lists and `zoomBounds` JSON |
| Activity | `docs/resources/data/activity.json`  | UUIDs, geocoded `lat`/`lng` |
| Location | `docs/resources/data/location.json`  | UUIDs, geocoded `lat`/`lng` |
| Routes   | `docs/resources/data/routes.csv` + `docs/resources/geojson/*.geojson` | UUIDs, great-circle routes (plane), driving routes (auto/train), hike GeoJSON references |

## Typical workflow

1. Edit the Google Sheet for the relevant tab.
2. If a new auto/train route has an unusual location name, add it to the `manual_locations` dict in `extract_data.py` (see [Manual coordinates](#manual-coordinates) below).
3. Run the script from the project root:

```bash
python scripts/extract_data.py
```

4. Review the generated files in `docs/resources/`.
5. Commit.

## Usage

```bash
# standard run — reads sheets, writes files, uploads enriched data back to sheets
python scripts/extract_data.py

# dry run — skips writing back to Google Sheets
python scripts/extract_data.py --no-upload

# override the spreadsheet key
python scripts/extract_data.py --sheet-key YOUR_SHEET_KEY

# verbose / debug output
python scripts/extract_data.py --verbose
```

## Configuration

`api_keys.json` must be present in the project root. It should contain a Google service-account key (for Sheets access) and optionally an OpenRouteService key (for driving/train routes):

```json
{
  "type": "service_account",
  "project_id": "...",
  "...",
  "google_sheets_key": "YOUR_SPREADSHEET_ID",
  "openrouteservice": "YOUR_ORS_API_KEY"
}
```

> `api_keys.json` is listed in `.gitignore` and should never be committed.

## Geocode caches

Successful geocoding results are stored locally to avoid redundant API calls:

- `scripts/geocode_cache.json` — Activity and Location (Nominatim)
- `scripts/geocode_cache_routes.json` — Routes (OpenRouteService Pelias)

Delete or edit an entry to force a re-geocode on the next run.

## Google Sheets field reference

### Overview

The Overview sheet describes Waypoint markers on the map. Fields are filled in manually.

| Field | Notes |
|-------|-------|
| `id` | Set with `=ROW()-1`. Not auto-generated by the script. |
| `name` | Displayed prominently in the popup and hover tooltip. |
| `lat` / `lng` | Copy from Google Maps, or use `legacy/lat_lng_geopy.ipynb`. |
| `start_date` / `end_date` | Not yet used by the front end. |
| `photo_album` / `photos` | Must match the **exact** folder and filenames (case-sensitive). Structure `photos` as a Python list. |
| `description` / `notes` | Optional. Both appear in the popup. |
| `importance` | Subjective 1–10 scale; controls marker size. |
| `visit_type` | Set to `"school"` to add a school icon to the popup. |
| `home` | Set to `TRUE` to style the marker border as a home location. |
| `zoomBounds` | JSON array `[[south, west], [north, east]]` — zooms the map to a bounding box when clicked. |
| `zoomLevel` | Zoom level to jump to when the popup is opened. |

### Activity

Activities are point features (hikes, events, etc.) that appear on the map at a specific location. The script auto-assigns IDs and geocodes missing coordinates.

| Field | Notes |
|-------|-------|
| `activity_id` | Auto-generated UUID. Do not edit once set. |
| `name` | Displayed prominently in the popup and hover tooltip. |
| `location` | Plain-text location used to geocode `lat`/`lng` if those columns are empty. |
| `lat` / `lng` | Auto-filled via geocoding if blank. |
| `activity_type` | Must match an icon key in `docs/static/js/visualizationSettings.js`. |
| `route_path` | Filename of a GeoJSON route. Enables the Routes layer on zoom and auto-adds the row to the Routes sheet as a `hike`. |
| `description` / `notes` | Optional. Both appear in the popup. |
| `photo_album` / `photos` | Must match the **exact** folder and filenames (case-sensitive). Structure `photos` as a Python list. |

---

### Location

Locations are persistent place markers (museums, parks, landmarks, etc.) distinct from one-off activities. Behaves the same as Activity for ID generation and geocoding.

| Field | Notes |
|-------|-------|
| `location_id` | Auto-generated UUID. Do not edit once set. |
| `name` | Displayed prominently in the popup and hover tooltip. |
| `location` | Plain-text location used to geocode `lat`/`lng` if those columns are empty. |
| `lat` / `lng` | Auto-filled via geocoding if blank. |
| `location_type` | Must match an icon key in `docs/static/js/visualizationSettings.js`. |
| `description` / `notes` | Optional. Both appear in the popup. |
| `photo_album` / `photos` | Must match the **exact** folder and filenames (case-sensitive). Structure `photos` as a Python list. |

### Routes

Routes are linear features drawn on the map (flights, drives, hikes, etc.). The script auto-assigns IDs and generates GeoJSON geometry for most transport modes.

| Field | Notes |
|-------|-------|
| `route_id` | Auto-generated UUID. Do not edit once set. |
| `start_location` / `end_location` | Used for geocoding and route generation. For finicky locations, add manual coordinates — see [Manual coordinates](#manual-coordinates). |
| `transport_mode` | Controls route generation and map styling. Accepted values: `auto`, `plane`, `boat`, `train`, `hike`. |
| `filename` | GeoJSON filename. Auto-generated for `auto`, `plane`, and `hike`. Must be set manually for `boat` and `train` (if providing a real route). |

#### Transport modes

| Mode | Behaviour |
|------|-----------|
| `hike` | Automatically added from Activity rows that have a `route_path`. Can also be added manually. Source GeoJSON from [Overpass Turbo](https://overpass-turbo.eu/). |
| `plane` | Generates a Great Circle route, with correct handling of the International Date Line. Use airport names for `start_location`/`end_location` for best geocoding results. |
| `auto` | Driving route via OpenRouteService. Geocoding can be unreliable for ambiguous place names — add to `manual_locations` if it fails. |
| `train` | Must be added manually (ORS does not support rail routing). Source GeoJSON from [Overpass Turbo](https://overpass-turbo.eu/) and trim with `resources/trim_geojson.ipynb`. If no `filename` is provided the script falls back to a driving route styled as a train. |
| `boat` | Must be added manually. Source from [Overpass Turbo](https://overpass-turbo.eu/) for ferry routes or draw with [geojson.io](https://geojson.io/). Trim with `resources/trim_geojson.ipynb`. |

Overpass Turbo queries used to source route GeoJSON are archived in `resources/overpass_routes.ipynb`.

#### Recommended tools:

- [Overpass Turbo](https://overpass-turbo.eu/)
- [geojson.io](https://geojson.io/)

### Manual coordinates

Some place names cannot be geocoded reliably. These coordinates are stored in `scripts/manual_locations.py`. 

The script always prefers manual coordinates over geocoding services.

For `auto` routes (and `train` driving routes styled as trains) where ORS geocoding fails or returns the wrong location, add the coordinates to the `manual_locations` dict in `scripts/manual_locations.py`:

```python
# format: "Spreadsheet location name": (longitude, latitude)
manual_locations = {
    "Fish River Canyon": (17.614818, -27.589350),
    ...
}
```

The name must match the `start_location` or `end_location` value in the spreadsheet exactly.
